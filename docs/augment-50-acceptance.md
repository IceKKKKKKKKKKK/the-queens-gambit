## 1. 功能与兼容门槛

- 目录必须恰好包含 50 张稳定 ID：黑桃 13、红桃 13、梅花 12、方块 12。
- 每张牌必须有服务端可执行效果；不允许只增加名称、描述或客户端动画。
- 旧 20 张的语义保持不变，经典模式不得接受任何军令动作。
- 已持久化的 `junqi-augments-v1` 对局必须能迁移、继续、重连和回放。
- `junqi-augments-v1` 的“定点侦察”和“前沿侦察”保留旧候选语义：符合原条件的已知存活敌棋与已公开军旗仍可被选择或随机抽中；`junqi-augments-v2` 则只提供未知目标并排除已公开军旗。
- 两轮发牌必须保持同档、双方独立三选一、单格刷新、已见不再出现。第二轮只排除在中局无效的牌，而不是按整套花色排除。
- 主动牌、自动牌、布阵牌、时钟牌、侦察牌、额外行动与战斗牌都必须进入无路可走判断、投影隐私、事件与回放覆盖。
- 新建强化排位在合法落子扣时后若余时不高于五分钟，完整增加五秒且不封顶于五分钟；主动放弃追加行动不加秒，军令棋钟返还可与排位加秒叠加。热部署前已持久化且缺少新制标记的对局继续使用旧上限，避免中途变更规则。
- 只有新建 v2 强化对局在第二轮公开后启用三次重复局面和棋；第二次出现必须公开显示 `2/3` 提示，第三次出现立即终局。经典模式和 v1 强化对局保持原样，不得被新版补判和棋。
- 三次重复和棋在排位中按双方各 `0.5` 分结算并各增加一局和棋；评分与比赛落库必须幂等。客户端只能收到公开出现次数，不能获得服务端摘要、盐或完整重复历史。
- 未登录玩家邀请 secret 只从 URL fragment 暂存到同一标签页 `sessionStorage`，认证返回地址只保留房间号或无 secret 重试标记；服务端 HTML 不得回显 secret。观战路径必须保留 `watch=1`，且不得读取、覆盖、消费邀请或尝试申领玩家席位。

## 2. 动画门槛

标准动效状态机：

1. 三张候选牌按 70–110 毫秒错峰从下方弹入，落点无抖动。
2. 锁定后，未选两张淡出并禁用交互；选中牌平滑居中。
3. 选中牌围绕 Y 轴旋转 720°；背面阶段必须显示原创、平面化的纸牌背板花纹。
4. 旋转结束后缩放并飞入左侧自己的军令牌盒；服务端确认慢、重连或超时代选不得重复播放或卡死。
5. 主动牌本身承担按钮交互；一次性牌耗尽时播放烧边、火星、灰烬消散，多充能牌只更新次数。
6. `prefers-reduced-motion` 下跳过大位移、旋转与焚毁，仅保留短淡入淡出和最终状态。

逐帧检查至少覆盖 390×844、768×1024、1440×1000；在每个关键帧检查溢出、遮挡、锯齿、错误层级、焦点、重复点击与文字可读性。

## 3. 策略与平衡门槛

平衡数据只使用不知道敌方暗子真实类型的策略机器人。每一组评估都交换黑白、交换先手并使用配对种子。

- 策略至少包含：合法候选生成、公开信息局面评分、有限深度搜索或 rollout、确定性随机源，以及同档 best-response 选择。
- 报告每张牌的选择次数、可发动局、实际发动局/次数、首次发动手数、胜负、配对胜率、置信区间和先手偏差。
- 同档调整目标：在足量配对样本中，校正先手后的点估计尽量落在 45%–55%；95% 区间仍过宽时只能标记“样本不足”，不能宣称平衡。
- 另做不改变正式发牌规则的跨档实验，验证黑桃、红桃、梅花、方块的平均影响方向总体递减；非布阵焦点牌必须同时覆盖“高档第一轮/低档第二轮”和反向顺序，第二焦点只能在引擎完成第 9 手并正式进入第二轮 draft 后选择与公开，严禁在 move 0 注入。
- `setup` 牌只能作为第一轮焦点并进入独立 setup 专层；该层可评估布阵牌本身，但不得混入轮次交叉平衡的纯档位结论。跨档逐腿证据必须保存轮次顺序、结束原因、末钟、焦点发动/机会、封顶、卡死和异常。
- 跨档配对种子只能由 cycle、档位 comparison、赛程 ordinal 与 round order 派生，不得包含卡牌 ID；同一轮次顺序的四条换色/换先手腿共享一个处理无关种子。档位聚合必须先按卡等权，再使用镜像组级确定性 bootstrap 区间；不得把重复次数较多的卡隐式加权，也不得用小样本逐局 z 区间宣称方向得到确认。
- “持有但无机会发动”超过 70%、或同档 best-response 差异超过 10 个百分点的牌必须进入调整队列。
- 数值调整一次只改变一个明确参数（次数、时间、距离、侦察数量等），保留调整前后配对种子，防止把随机波动当成改善。
- 搜索机器人只能提供强度信号，不能证明全局最优或真人环境绝对平衡；最终仍需真人盲测。

当前跨档证据的产品引擎指纹为 `augment-duel-dark-v2:threefold-3:strategic-sha256-v1`。强搜索使用每局最多 300 手、`4×8×3`，而正式同档 soak 仍使用 180 手、`4×8×3`；两套证据用途不同，不能合并 checkpoint 或互相替代。强搜索六组高档点估计为 54.3%、56.5%、49.4%、44.4%、53.4%、53.8%，四档卡等权点估计为黑桃 53.7%、红桃 46.9%、梅花 50.5%、方块 47.8%；所有对应 95% 区间都跨过 50%。

## 4. 四小时持续压测

从最后一次规则或动画修改后重新计时，持续至少 4 小时。中途修改会使本轮计时失效并重新开始。

截至 2026-08-10 ET，这一正式运行尚未开始。预检、跨档强搜索、短 smoke 或框架恢复测试都不能计入下面的四小时门槛。

压测必须写入可恢复检查点和机器可读汇总，并并行覆盖：

- 完整对局与搜索策略对弈；
- 发牌、刷新、重连、第二轮截止、投影与回放状态机；
- 所有 50 张牌的选择、执行或明确的不可自然触发缺口；
- API 并发、房间版本冲突、排位结算幂等和观战脱敏；
- 动画状态的快速重复选择、慢响应、超时、重连与 reduced-motion 路径。

失败条件包括：未捕获异常、非法状态、活棋重叠、负棋钟、回放分叉、隐藏信息泄露、无动作卡死、重复结算、动画永久遮挡、横向溢出、焦点逃逸或进程非预期退出。发现任何失败后修复、补回归，并从最后一次修改后重新运行完整四小时。

最终报告必须记录提交、目录版本、运行起止时间、总局数/手数/搜索节点、每张牌覆盖、失败与修复、平衡调整前后结果、桌面/手机逐帧证据，以及仍无法由自动化证明的边界。只有这些证据齐全且最后一轮四小时无失败，才能宣布自动化与冻结版本验收完成；真实三人、跨浏览器和辅助技术结果另列为公开测试后的扩展验证，不得用自动化结果代替。
