# 军令强化：隐藏信息策略搜索与高强度平衡赛

`scripts/augment-balance-simulation.ts` 是独立于规则目录和 UI 的可恢复对弈框架。它动态读取 `AUGMENT_CATALOG`，因此目录从 20 张扩到 50 张后不需要维护一份重复卡表。它的目标是持续发现状态机故障、不可发动的军令、同花色强度离群、选牌策略偏差和先手/颜色偏差，并生成可审阅的调参候选。

它不是“平衡已经被数学证明”的工具。有限深度机器人、近似信念分布与自动对局不能证明全局最优策略或纳什均衡，也不能替代真人暗棋中的欺骗、记忆、风险偏好和盲测。

## 信息隔离

每次决策先调用真实服务端的 `projectGame(state, side)`，机器人只能读取该玩家在产品中能看到的内容：

- 己方棋子身份、双方位置、已经公开或被侦察的敌子身份；
- 已公开的双方军令、己方待处理侦察、棋钟、公共行动结果；
- 不读取未公开敌子的真实 `type`，不以真实身份给候选走法加分。

搜索会从标准 25 子库存扣除已知身份，再用固定种子为未知敌子采样若干个“可能世界”。候选行动只用投影视图生成；每个候选在这些可能世界中执行，并用有限深度可见信息 rollout 估值。真实隐藏身份被换位后，只要玩家投影不变，相同种子必须产生完全相同的决策指纹；独立测试固定验证这一点。

战斗结果在假想行动后可以参与估值，因为玩家执行该行动后确实会看到存活/同归于尽/夺旗结果。这是对不确定结果求期望，不是提前读取敌子身份。

v11 还把产品引擎公开的重复局面出现次数纳入投影。确定化只能把公开的 `currentOccurrences` 重新绑定到本次采样世界，并为采样世界生成新的摘要证据；它不能复制真实对局的私有摘要、服务端盐或完整重复历史。这样搜索既能正确估计“下一次重复可能和棋”，又不会用隐藏世界身份作为旁路信息。

## 同 tier 循环赛

赛程按花色分别建立完整 round-robin。每一对同花色军令组成一个镜像组，每个镜像组固定四局：

1. A 黑、B 白、黑先；
2. B 黑、A 白、黑先；
3. A 黑、B 白、白先；
4. B 黑、A 白、白先。

因此 A/B 都会以黑白双方出现，也都会先手和后手。当前 50 张目录为 13/13/12/12 张，完整一轮自动产生 288 个配对、1,152 局；这个数字由目录实时计算，不写死在脚本中。开局焦点军令由合法三选一状态机锁定；第二轮仍按真实规则生成三选一和一次刷新。

同组四腿共享同一个 `pairedSeed`，所以基础布阵、思考耗时随机流与服务端随机基种一致；四腿只改变焦点牌的黑白归属和谁先走。机器报告保留 `groupKey → pairedSeed` 台账，并拒绝同一个组以另一个 seed 重复累计。

策略搜索采用 Common Random Numbers 降低处理组之间的随机方差。每局以本地 `decisionOrdinal` 标记第几次走子决策；可能世界与引擎/rollout 随机带只由 `pairedSeed + decisionOrdinal + channel + sample` 派生，不读取行动日志长度、手数、行动方、可见状态指纹、军令 ID、剩余次数、棋钟或已揭示棋子身份。同一次决策、同一个确定化样本下，所有根候选共享完全相同的隐藏世界与引擎随机流。候选静态同分时用去掉军令 ID 的几何动作键稳定排序，普通移动与相同起终点的军令移动视为同一个配对动作；完整动作键仍保留在报告中用于唯一识别。这只控制外生随机数，不会抹掉军令造成的合法行动、条件信息或局面估值差异。

第二轮选牌会组合三个信号：军令效果的静态先验、此前镜像赛得到的经验评分、对已公开敌方军令的 matchup 反制值。如果未知池的预期收益明显高于当前最弱选项，策略会刷新最弱槽位。随着 checkpoint 累积，对局会从静态策略逐渐过渡到经验 best response；报告同时列出每张牌最容易压制的目标和最难应对的 counter。

走子策略会枚举普通行动、主动移动、主动换防和待处理侦察目标，先按可见信息剪枝，再进行确定化样本和有限深度 rollout。高强度模式默认 4 个可能世界、8 个候选分支、3 层 rollout。这个搜索比随机/短视机器人更强，但报告会始终明确：它不是全局最优证明。

## 运行

项目要求 Node 22+。结构快速赛会遍历完整同花色配对，但采用较短对局和较小搜索，用来检查全目录可运行性：

```text
node --experimental-transform-types scripts/augment-balance-simulation.ts --mode=quick
```

四小时高强度持续赛：

```text
node --experimental-transform-types scripts/augment-balance-simulation.ts --mode=soak --duration-minutes=240
```

高强度默认值：

- 180 个有效行动上限；
- 每次决策 4 个隐藏身份确定化样本；
- 最多 8 个候选行动；
- 3 层可见信息 rollout；
- 模拟思考耗时每步 2.5–6.5 秒，使正式 10 分钟棋钟及时间类军令进入测试范围；
- 每一对军令每轮一个四局镜像组，完成目录后从下一 cycle 继续。

所有数值均可用 `--max-actions`、`--determinizations`、`--branching`、`--rollout-depth`、`--think-min-ms`、`--think-max-ms`、`--mirror-groups-per-pair` 和 `--seed` 覆盖。`--pair-limit=N` 只用于开发烟雾测试；`--pairs-per-suit=N` 会从每个花色的 pair 列表中等距抽样，适合跨四档运行性能 pilot。两种抽样都会进入赛程指纹，不能误续接到完整赛程，也不能同时使用。

候选剪枝会先按不含军令 ID 的行动几何去重；普通移动与军令移动可到达同一位置时，保留不消耗次数的普通移动。搜索宽度至少为 3 且普通移动与其他行动并存时，最多一半槽位固定留给当前评分最高的普通移动；追加行动的主动放弃仍固定保留一个槽位，其余槽位按全局评分补齐且不重复。单分支 rollout 继续使用原有的全局最高分行动，不应用分层保留。

## 180 手运行性能 pilot

30 手 quick 中大量 capped 的原因不是状态机卡死，而是结构赛上限明显短于机器人自然完赛长度。用 `--pairs-per-suit=2 --max-actions=180 --determinizations=4 --branching=8 --rollout-depth=3` 对四个花色等距抽取 8 个镜像组后：32/32 局自然结束，异常和卡死均为 0；合计 1,703 个行动、160,804 个搜索节点，实测 347.8 秒，即每组约 43.5 秒、每局约 10.9 秒，平均自然局长约 53.2 手。

按当前机器线性外推，288 个同档镜像组约需 3.48 小时，所以 4×8×3 是能在四小时预算内完成至少一轮全目录的最高已验证深度。4×8×4 的单组基准为 66.1 秒，外推完整一轮约 5.29 小时，因此没有作为默认值。这个预算是当前硬件和当前目录上的工程估计，不是运行时承诺；soak 仍按 wall-clock 在完整四腿组边界停止，并保留 checkpoint。

## Checkpoint、恢复与输出

每完成一个四局镜像组，脚本就原子写入 checkpoint。进程在组内中断时，该组不会被登记；恢复后会安全重跑，不会把半个镜像组混入统计。默认文件：

- `outputs/balance/augment-balance-checkpoint.json`
- `outputs/balance/augment-balance-report.json`
- `outputs/balance/augment-balance-report.md`

恢复命令必须使用完全相同的目录、种子、搜索参数和配对范围：

```text
node --experimental-transform-types scripts/augment-balance-simulation.ts --mode=soak --duration-minutes=240 --resume
```

每次 `--resume` 的 `--duration-minutes` 表示本次进程继续运行的 wall-clock 时长。checkpoint 会验证 schema、目录指纹、搜索配置指纹、赛程指纹、`BALANCE_ALGORITHM_VERSION`、产品引擎规则指纹和已完成组 key 的唯一性；跨档恢复还会按当前 options 与 cursor 重建计划前缀，逐腿核对规范换色/先手模板及处理无关 seed，再仅从 raw 四腿台账确定性重建全部 aggregate 并深比较。raw 字段、组、seed 或派生统计任一缺失、重复、额外或被篡改都会拒绝恢复。策略、搜索、产品和棋规则或统计口径改变时必须更换对应版本/指纹；它们都会进入同档与跨档的配置指纹，因此旧 checkpoint 会被明确拒绝，不能把不同引擎或机器人算法的证据混在一起。

当前证据版本为 `hidden-info-balance-v11-threefold-public-occurrence`，产品引擎规则指纹为 `augment-duel-dark-v2:threefold-3:strategic-sha256-v1`。它在生产时序、轮次交叉、setup 分层、逐腿审计、卡等权聚合和镜像组 bootstrap 的基础上，加入产品三次重复终局、公开出现次数的安全确定化和 `0.5` 和棋评分。任何算法版本或引擎规则指纹不一致的旧 checkpoint 都只能作为历史记录，不能恢复或合并进当前报告。

JSON 是权威机器可读输出，包含：

- 每张军令的参与局数、胜负和、发动局/次数、三选一出现/选择次数，以及由该军令授予却被策略主动放弃的追加行动次数；
- 同花色每个 pair 的镜像分和置信区间；
- 黑白胜率、先后手胜率、结束原因、未完成、行动上限、卡死、异常和全局 `pass_extra_move` 选择次数；
- 实际评估的搜索节点总数，以及每个镜像组共享的 `pairedSeed`；
- 最优攻击目标、最难 counter 和经验策略数据；
- 只读调参建议、未知主动效果类型及解释边界。

## 统计口径

普通胜率用 Wilson 95% 区间。强度判断优先使用“四局镜像组得分”：胜 1、产品引擎裁决的 v2 三次重复和棋 0.5、负 0，再在镜像组层面计算均值与 95% 区间。这样至少把同一组内的换色/换先手相关性保留在同一统计单位中，避免把四局错误当成四个完全独立样本。`maxActions` 到界仍是未完成的 `capped`，不能改名或折算成和棋；经典模式和 v1 也不会被模拟器补判三次重复。

选中率是第二轮真实三选一中 `picked / offered`；发动率是持有该军令的对局中至少发动一次的比例。开局焦点牌是实验强制变量，不计入“自然选中率”，但计入持有、胜负、发动和镜像强度。

“没有发动”不会直接被解释成“弱”。每个实际回合都从该玩家的投影视图枚举主动军令的合法行动：只要出现过合法主动动作，该局计入 `opportunityGames`；自动牌只有真实触发时才计为出现机会；布阵牌在受控布局实际使用许可时计为有机会。报告同时给出“持有但整局无机会率”和首次发动手数的原始样本、均值、中位数、四分位及 0、1–9、10–29、30–59、60–119、120+ 分桶。

`searchNodes` 的口径是每个候选行动在每个确定化世界的根节点，加上实际执行的 rollout 节点；候选生成或静态排序不虚增节点数。`passExtraMoves` 只在策略实际选择 `pass_extra_move` 时增加，并按当时授予追加行动的军令精确归因；同档报告保留全局、pair 和逐卡计数，跨档报告额外拆出每组 comparison 的高档/低档计数。

调参建议器只有在同花色至少三张牌有数据、单卡至少八个镜像样本且偏离 tier 均值至少 6 个百分点时才会输出。它只建议：

- `charges` 加减 1；或
- 已存在的 `bonusMs`、`count`、`maxTriggers`、`rowsFromFront`、`allowance` 等数值做小步调整。

建议不会写回 `lib/augments.ts`。每次实际改数值都必须由开发者审阅，再从新目录指纹开始一轮全新测试，不能把改动前后的样本混合。

## 自动验证

`tests/augment-balance-harness.test.ts` 独立覆盖：

- 隐藏敌子身份互换后的决策信息隔离；
- 相同种子、目录和参数得到相同四局镜像结果；
- 换色与换先手四腿结构；
- 同档 Wilson/镜像组均值区间，以及跨档确定性镜像组 bootstrap 区间；
- checkpoint JSON 往返、算法版本/配置验证、旧统计结构拒绝、重复 key 拒绝与断点续跑去重；
- 对手私有侦察、临时情报或追加行动状态变化后，根玩家决策仍保持完全一致；
- CRN 不受事件条数、军令、剩余次数、棋钟或揭示身份影响，不同决策序号不会复用随机带，同一样本的所有候选共享随机带；
- 配对状态键会响应回合与棋子几何变化，配对动作键会合并相同几何的普通/军令移动，同时完整可见指纹和动作键仍保留处理差异；
- 搜索节点公式、机会局与首次发动手数聚合；
- 四花色等距 pilot 抽样的确定性和目录动态性；
- 独立跨档全目录赛程、真实第 10 手 draft、非 setup 双轮次顺序、setup 专层、卡等权聚合和四腿处理无关 seed 台账。

## 独立跨档全目录校正（不混入正式匹配统计）

正式玩法只允许双方同档抽牌，因此同档 round-robin 不能回答“黑桃是否整体强于红桃、红桃是否强于梅花”这一档位方向问题。独立脚本枚举六种高档/低档花色组合，并用轮换式卡对覆盖 50 张目录。当前 13/13/12/12 目录在 cycle 0 先形成 77 个卡对；每个非 setup 卡对再生成“高档第一轮”和“低档第一轮”两组四腿镜像，setup 卡对只生成布阵牌所在花色第一轮的合法组。计划合计 142 个镜像组、568 局，其中纯轮次交叉层 130 组，setup 专层 12 组：

```text
node --experimental-transform-types scripts/augment-cross-tier-calibration.ts --mode=quick
node --experimental-transform-types scripts/augment-cross-tier-calibration.ts --mode=soak --duration-minutes=60
```

当前跨档校正证据显式使用每局最多 300 手、4 次确定化、8 个候选和 3 层 rollout，以避免把少数长局封顶误混入完整镜像组。正式同档四小时 soak 仍固定为 180 手、`4×8×3`；180 是同档 288 组在四小时预算内的工程配置，300 只属于独立跨档校正，二者报告和 checkpoint 不得混合。

输出保存在独立的 `cross-tier-*.json/md`，不会写入正式同档 card mirror aggregate。每条腿保存 round order、结束原因、末钟、焦点牌发动次数/机会、第二轮开始手数、第二轮是否公开、封顶、卡死与异常；报告分别标明“已执行组”和“完整镜像组”，不能把未完成或未真实到达第 10 手并公开第二焦点的组写成完整证据。六种纯轮次组合用卡等权点估计与镜像组级确定性 percentile bootstrap 区间；逐档也先计算每张卡自己的均值，再让卡等权，避免 13×12 轮换中某张牌因重复次数更多而获得更高权重。少于 8 个完整镜像组时，方向固定写成 `insufficient`，区间不使用具有确认意味的逐局 z 近似。

报告的 `acceptancePass` 是方法学门槛，不是“高档点估计胜出”的别名。它只在计划赛程全部执行且四腿完整、每腿真实到达并公开第二轮、无异常/卡死/封顶/时序违规、50 张目录覆盖、46 张非 setup 卡完成双轮次顺序、4 张 setup 焦点完成专层覆盖，并且六个纯轮次 comparison 全部达到样本门槛时为真。`pointEstimatePass`、`tierPointEstimatePass` 与 bootstrap 方向只描述观察到的强度，不参与方法学验收；短样本和 `plannedGroups=null` 的持续运行均不会被写成正式通过，CLI 也会以非零状态结束。

这是 synthetic direct 对决，但生产时序不能被简化：move 0 只存在已公开的第一轮，机器人必须真实完成前 9 个合法落子，由游戏引擎进入正式 `augment_draft` 后，实验才把第二焦点放进本人候选并通过标准选择/锁定流程同时公开。另一档位的主动移动占位牌仅用于满足双方每轮都要选牌的结构约束，选中后以 charge 上限耗尽，不产生伪造的 `augment_used` 事件，也不进入焦点牌统计。非 setup 卡对同时交换轮次顺序；setup 牌只允许第一轮并独立报告，绝不混入纯档位排序。paired seed 只由 cycle、档位 comparison、schedule ordinal 和 round order 派生，不包含卡 ID；同一镜像四腿共享种子。轮换对手仍小于全笛卡尔积，因此需要多个 cycle 与真人盲测，不能把结果称为全局最优或完整交互证明。
