# 军令 · 强化陆战棋

在线二人暗军棋，包含经典模式，以及在经典规则上增加两轮“军令强化”选择的强化模式；同时支持账号、邀请、匹配、棋钟、观战和逐手复盘。

本文中的“海克斯”是开发阶段对强化机制的类比，当前产品和代码统一称为“军令”或“强化牌”，不是棋盘上的六边形坐标。

## 强化模式怎么进行

1. 第一轮发生在布阵期。服务器先确定双方共用的花色，再分别给双方独立的三张候选牌。
2. 每名玩家每轮可定向刷新一个槽位一次；看过、刷掉或新刷出的牌都会进入本人本局的 `seen`，之后不再出现。
3. 双方各自锁定一张后同时公开。第一轮的布阵牌会在开局事务中校验并生效。
4. 完成前 9 个全局有效落子后、执行第 10 手前暂停棋钟，进入第二轮三选一。
5. 第二轮花色必须不同于第一轮，并逐张排除 4 张 `setup` 布阵牌；方块剩余 8 张中局牌仍可出现。
6. 第二轮选择限时 45 秒。超时时保留已选项；未选择的一方由服务器确定性锁定当前第一张候选。
7. 主动牌由玩家在合法时机点击使用；自动牌由服务器按触发条件结算。追加行动最多一步且不可连锁；除“胜势推进”明确允许同一枚棋继续行动外，其余相关牌要求换另一枚棋。

强化排位的标准棋钟是每方 10 分钟。合法落子扣除思考时间后，若该方剩余时间不高于 5 分钟，则完整返还 5 秒，因此恰好 5:00 会变为 5:05；布阵和第二轮选牌期间暂停对局棋钟，主动放弃追加行动只扣思考时间、不返还这 5 秒。

只有新建的 `junqi-augments-v2` 强化对局在第二轮公开后启用三次重复局面和棋。相同已结算战略局面第二次出现时，双方看到公开的 `2/3` 提示；第三次出现立即和棋，排位按双方各 `0.5` 分结算。经典模式和持久化的 v1 强化对局不采用这项新规则。

未登录玩家在同一标签页打开玩家邀请时，客户端只把 URL fragment 中的邀请 secret 暂存在 `sessionStorage`，随后清除 fragment；登录 URL 和服务端渲染 HTML 只携带房间号或无 secret 的重试标记，不包含邀请 secret。登录返回同一标签页后才读取暂存值申领席位并清除；`watch=1` 观战路径不读取、替换或消费玩家邀请。

## 当前验证状态

以下记录截至 2026-08-10 ET。`outputs/` 被 Git 忽略；规则、参数或算法改变后，旧报告与检查点只能作为历史记录，不能混入当前结论。

### 已有证据

- 最终邀请修复后的完整回归共 200 项，全部通过：HTML 9 项、TypeScript 188 项、真实集成 3 项；
- 生产构建、全项目 ESLint、`tsc --noEmit --incremental false` 与差异检查均通过；
- v11 低深度预检从空检查点完成 142 个镜像组、568 条腿，`acceptancePass=true`；
- v11 强搜索完成 2 个 cycle、284 个镜像组和 1,136 条腿；结束原因为夺旗 1,031、无棋可走 97、三次重复和棋 8，封顶、异常、卡死和第二轮时序违规均为 0，`acceptancePass=true`；
- 576 条腿的定向强搜索 A/B 没有让“扇区侦察”或“工兵誓约”的候选改动通过预注册门槛，因此两张牌均保留当前数值；
- 390×844、768×1024、1440×1000 三档界面与关键军令动画已有逐帧截图证据。

在上述自动化和受支持的 Chrome 视口证据范围内没有已知 P0/P1。它仍不替代真人联机、跨浏览器、辅助技术、正式四小时持续测试或生产环境验证。

## 平衡测试参数与复现

项目要求 Node.js 22 或更高版本。

```powershell
npm install
npm run dev
```

完整代码检查：

```powershell
npm test
npm run lint
npx tsc --noEmit
```

当前 v11 两 cycle 跨档强搜索证据使用每局最多 300 手；这是跨档校正参数，不改变正式同档 soak 的 180 手上限：

```powershell
node --experimental-transform-types scripts/augment-cross-tier-calibration.ts --mode=quick --cycles=2 --seed=20260809 --max-actions=300 --determinizations=4 --branching=8 --rollout-depth=3 --think-min-ms=2500 --think-max-ms=6500
```

同档完整 quick 会动态产生 288 个四腿镜像组、1,152 局，默认使用 30 手、`1 × 3 × 1` 搜索：

```powershell
node --experimental-transform-types scripts/augment-balance-simulation.ts --mode=quick
```

同档四小时高强度对弈使用 180 手、`4 × 8 × 3` 搜索：

```powershell
node --experimental-transform-types scripts/augment-balance-simulation.ts --mode=soak --duration-minutes=240
```

最终四 worker 验收会并行运行 balance、rules、api、animation，并要求源码指纹不变、50 张覆盖和至少一轮完整同档赛程：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\soak\run.ps1
```

所有自动对弈都只允许机器人读取玩家可见投影；镜像组交换黑白和先后手并共享配对 seed。有限深度机器人只能提供强度信号，不能替代真人暗棋盲测或证明全局最优。
